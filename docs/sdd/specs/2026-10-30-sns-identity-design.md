# 会話とストリークで育つSNSの見た目設計

分類: architectural。共有理解、B「ポップ大騒ぎ」の成長・明暗、設計第1〜4節と、両方の見た目・演出を1・7・30・60・100日の段階制へ揃える変更をユーザーが承認済み。Markdownを正本とし、隣接HTMLを同期する。本書は仕様書レビュー用であり、本体の実装・本番反映・実機検証の完了を示さない。

## 目的と範囲

- 友達との関係が育つことを主役にし、本人のストリーク達成を補助的な動機にする。モノクロから1・7・30・60・100日の節目で色・模様・装飾が増え、100日で思い切り派手になるSNSの個性を作る。節目間の見た目と100日以降の完成形を維持し、幼さを含むポップさを許容する。
- Chat Growth、Streak Appearance、チャット単位の共有プリセット、端末単位の演出設定、節目演出、既存データの移行を一つの機能として扱う。日本語、iOS・Androidを対象とする。
- ストリークの達成条件、抽選、送受信・未読・下書きの仕様は変更しない。ランキング、関係の採点、課金、自由な色入力・画像持ち込み、プッシュ通知、音・振動、新しい関係管理UIは対象外。
- 設計第1節は保存・同期、第2節は見た目・描画、第3節は演出制御・端末保存、第4節は導入・障害対応・検証に対応する。以下で各節の契約を具体化する。

## 既存仕様との差分と採用方式

- [基盤設計](2026-09-25-app-foundation-friends-ui-design.md)と[ホーム・チャット設計](2026-10-27-home-chat-design.md)の恒常的なモノトーン指定を、本書の適用範囲で成長型の見た目へ変更する。既存の明暗モード、時間帯指定、画面構成、認証・アカウント分離は継承する。
- 採用方式Aは、サーバーに日別の達成記録と累計を保存する方式。二重加算を防ぎ、一覧の読み取りを軽くし、日別記録から累計を検証・再構築できるようにする。
- 日別記録だけを保存して表示時に件数を読む方式Bは、読み取り時の集計が増えるため採用しない。メッセージ履歴を毎回集計する方式Cは、履歴量に応じて読み取りが重くなるため採用しない。
- 既存バックエンドを拡張し、別の成長サービス・認証・送信待ち基盤・定期ジョブは新設しない。ADRの3条件が全て成立する判断はなく、理由・数値・順序保証を本書に保持する。
- [Bの比較試作](../spikes/2026-10-29-sns-identity.html)は使い捨ての視覚的な参考資料。共有設定、順次再生、スキップ、永続化まで実装した製品見本ではない。挙動は本書を優先し、試作のHTML・CSSをネイティブアプリへそのまま移植しない。

## 構成と責務

- サーバーは受付時刻、成長日、累計、獲得済み見た目、共有プリセット、変更権限、操作の重複を確定する。クライアントのメッセージ集計や端末時計を正本にしない。
- 既存のホーム・会話リポジトリが確定値をアカウント別に取り込み、更新版とセッション寿命で古い応答を排除する。成長状態だけの独立した同期基盤は作らない。
- 既存ThemeProviderは端末の明暗解決を維持する。認証済み画面の見た目を管理する層と、会話内だけを上書きする層を分ける。見た目の計算は画面から独立した純粋関数にする。
- 装飾の描画と演出コーディネーターを分離する。コーディネーターは可視性、初回基準、消化済み節目、端末設定、再生順、スキップ選択を一元管理する。

## チャット成長の確定規則

- 同じ会話の2人が、同じ04:00 JST以上・翌04:00 JST未満の日に、それぞれ1件以上のサーバー受付済みメッセージを持つと、その会話に1日を加算する。両者の受付時刻が等しくてもよく、ストリークの厳密な返信順序を流用しない。
- 今日の対象者に限らず自由な会話を含み、本文のみ・画像のみ・本文と画像を同じ受付事実として扱う。抽選の未確定・失敗・対象外でもチャット成長は成立する。送信待ち・結果不明の端末表示だけでは加算しない。
- 1会話・1日につき最大1回。双方が何件送っても増分は1日であり、メッセージ件数や連続日数ではない。実際の累計は100日を越えて増やし、見た目だけを100日で上限にする。
- 会話しない日や友達解除で累計を減らさない。友達でない間は凍結し、再成立後は同じ会話で再開する。ブロック等の既存送信禁止を迂回しない。
- 同じ日にA送信、友達解除、再成立、B送信となった場合も、両方が各時点で正規に受け付けられていれば1日として数える。会話の識別をfriendship_epochで分割しない。
- 受付後のwithdrawn状態で加算を取り消さない。導入前の履歴も、残っている受付事実だけを使い、現在の本文検証で古い受付を無効化しない。物理的に残っていない履歴は推測しない。

## ストリーク由来の獲得済み見た目

- 現在のストリークと獲得済み見た目を別の状態として保持する。導入時はその時点の現在のストリークを基準にし、不明な過去最高ストリークを作らない。
- 獲得の根拠となるearned_daysは0〜100で、導入後に正しく適用したストリークの各途中値と既存の保持値の最大を使う。現在のストリークがリセットしても減らさず、この日数から到達済みの見た目段階を求める。
- 日付順の結果適用の中で各途中値を反映する。復旧処理の最後が0日でも、その処理内で29日へ達していればearned_days=29を保持し、見た目は7日段階とする。最終値だけを採取せず、保存値を7へ切り下げない。
- 同じストリーク日数を再達成しても、保持済み値を増やさない。最高日数を越えたらearned_daysを更新し、見た目は次の節目に達したときだけ進める。29日からリセット後の1日を足して30日扱いにはせず、次の30日段階には現在のストリークで30日を達成する。現在のストリーク自体は従来どおり100日以降も数える。
- 獲得済み見た目は本人だけの情報とし、友達検索・プロフィール・友達一覧へ追加公開しない。既存の現在のストリーク数値の公開条件は変更しない。

## サーバーデータと更新処理

### 保存する状態

- chat_growth_daysはconversation_idとdaily_keyを主キーとする日別達成記録。両者の送信が揃った日だけ作る。100日を越えた日も保持し、累計の根拠にする。
- chat_appearance_stateはconversation_idごとに1行。growth_days、固定のauto_preset_id、任意選択のselected_preset_id、catalog_version、共有設定のsettings_revisionを保持する。selected_preset_idが未指定なら固定の自動割り当てを使う。
- streak_appearancesはuser_idごとに1行。0〜100のearned_daysと見た目の版を保持する。earned_daysは節目間の数値も保持し、表示段階とは区別する。既存streaks.current_countの代わりにはしない。
- 導入後の新規ユーザーはearned_daysを0で開始する。新しい会話の状態も成長0日と固定の自動プリセットで初期化し、受付や明示的な設定保存のトランザクション内で欠落なく作る。
- 日別記録・会話状態は既存conversationsに、本人状態はprofilesに従属させる。友達関係の削除では消さず、アカウント削除に伴う既存の削除規則を無期限保持へ変更しない。
- 新しい表もRLSを有効にし、クライアントの直接読み書きを許可しない。認証付きの既存コマンド・クエリ境界からだけ扱う。

### メッセージ受付との一体化

1. 既存のlifecycle、ペア、ユーザー、会話のロック順と、受付成功済みメッセージの再試行規則を維持する。受付時刻は従来どおり会話ロック後のサーバー時刻にする。
2. 新しいメッセージの受付と同じトランザクション内で、同じ日付の両者の受付事実を確認する。相手・日付で絞った読み取りを使い、全履歴を画面取得ごとに集計しない。
3. 日別記録を一意に挿入できた場合だけgrowth_daysを1増やす。既存記録との衝突・同じ送信の再試行では加算しない。
4. チャット成長の処理は抽選成功の条件分岐の外に置く。従来のストリーク判定と、その日付順適用内のearned_days更新は既存の条件を守る。
5. 受付・日別記録・累計・判定可能な本人状態・操作結果をまとめて確定する。DB内の更新が失敗したら全体をロールバックする。

### 読み取り契約

- ホーム、一覧の各会話、会話詳細へchat_growthの確定日数とchat_appearanceの自動・選択中・実効プリセット、カタログ版、設定更新版、変更可否を追加する。
- ホームと会話詳細に、本人専用のstreak_appearanceとしてcurrent_streak、earned_days、見た目の版を含める。ホームの既存streakとcurrent_streakは同じスナップショットの同じ値にする。
- 会話詳細のチャット状態と本人状態を同じSTABLE読み取り・同じrevisionで返し、片方の別クエリが先に到着しただけで演出の順番を逆転させない。
- 未作成の会話でも、現在の友達への正規の取得なら、受付履歴がないことを根拠に確定0日と自動プリセットを返せる。端末の未取得状態と区別する。取得だけでconversationsを作らない。
- SQL、Edge、アプリのDTOを同時に更新し、新規項目の型・非負整数・版・プリセットIDを実行時にも確認する。古いキャッシュの項目欠落を0日へ型変換しない。

## 2人共通のプリセット設定

- Bの世界観に沿った、色・模様の組み合わせが定義済みのプリセットから選ぶ。各項目は安定したID、表示名、ライト・ダーク別配色、模様定義を持つ。カタログを版固定し、同じIDの意味や自動割り当てを無断で入れ替えない。
- 自動割り当ては正規化したペアと固定版から決定的に求め、会話作成前後で変えない。最初の永続操作で保存する。自動に戻すと元の割り当てに戻り、再抽選しない。
- 友達ごとの見た目が似ることは許容する。全会話での重複排除は保証せず、名前・画像を識別手段として残す。2人が異なる明暗モードでも、同じ実効プリセットの対応配色を使う。
- チャットヘッダーの「チャットの見た目」から見本を選び、「2人に適用」で確定する。見本の閲覧だけでは変更しない。「自動に戻す」も2人共通の変更とする。
- app-commandへset_chat_appearanceを追加する。入力はpeer_id、friendship_epoch、preset_idとし、preset_idの未指定ではなくnullを自動への復帰として明示する。実行者は認証から決め、成長日数・任意の配色・他人のIDを実行者指定として受け取らない。
- 現在の友達のどちらでも変更でき、相手の承認は不要。サーバーでも登録状態・参加者・現在の関係世代・ブロック・カタログ内の値を確認する。友達でない間は閲覧だけ許可し、設定変更は拒否する。
- 同じ会話の変更をロックで直列化し、後からサーバーに受け付けられた設定を採用する。端末時計は使わない。設定変更時にsettings_revisionを進め、2人へ再取得の合図を送る。
- 操作IDと入力の一致を検証し、成功済み操作の再試行は元の結果を返すだけで再適用しない。古い成功応答を現在の設定として直接上書きせず、クエリの確定状態を取り直す。
- オフラインで新しい変更を予約しない。確定するまでは最後に確認した見た目を維持する。結果不明はその操作ID・元の入力を保って確認し、別IDの変更として自動再送しない。同じIDでの確認が初回受付になる可能性も、後から受付順に反映されるものとして扱う。
- 結果不明の変更を抱えた端末では、解決前に別の変更を自動発行しない。入力・メッセージ送信は止めない。関係世代が失効した変更を、新しい世代の変更へ自動変換しない。
- 設定変更は成長日数や獲得済み見た目を増減させず、節目演出を発生させない。明暗・動き軽減・演出停止は各自のまま。友達解除後も設定を保持し、再成立時に同じ設定で再開する。
- 送信前に明示的な設定保存で会話を作ることは許可するが、それだけで空の会話を一覧へ追加しない。既存のメッセージ・下書き・今日の対象者による一覧条件を維持する。

## 同期・キャッシュ・プライバシー

- 既存chat_updatesは更新を知る合図のままにする。新しい会話状態の変更は当事者2人、本人状態の変更は本人だけのrevisionへ反映し、同じDBスナップショットで応答のrevisionを付ける。
- 新しい表を既存の汎用トリガーへ追加するだけで済ませない。conversation_idから参加者2人を解決する経路を用意し、日別記録・累計・設定の変更対象を正しく通知する。本文・達成内訳・共有設定の行をRealtimeで直接公開しない。
- revisionの増分を達成件数や演出イベント数にしない。初回、再接続、アプリ復帰、更新通知では正規クエリを再取得する。
- ホーム・一覧・未読の更新版一致、会話の世代・更新版、認証所有者のチェックを維持する。別アカウント、別相手、古い非同期応答で現在の見た目や演出状態を上書きしない。
- オフラインは最後に確認した見た目と最新でない可能性を表示する。初回未取得・新規項目がない旧キャッシュはモノクロの「確認中」とし、0日の確定や仮の獲得を作らない。
- 未知のプリセットや版は実行せず、利用できる直近の確定済み表示、なければ安全なモノクロへフォールバックする。装飾の解釈不能でメッセージ本文や下書きを消さない。
- 共有成長と共有設定は当事者だけが取得する。関係終了後のプロフィール・現在のストリーク取得禁止は継承し、本人の見た目を相手へ返さない。ログには本文・画像・認証情報を出さない。

## 見た目の成長段階

- Chat GrowthとStreak Appearanceの両方に、初期0と1・7・30・60・100日の共通段階を使う。チャットは確定した累計growth_days、本人は保持済みearned_daysを根拠に、超えていない最大の節目を表示段階とする。節目演出も同じ5つの到達点に揃える。
- 同じプリセット・明暗・端末設定なら、段階間は色・模様・装飾量・動きの強さを固定し、日数と次の節目までの残り日数だけを更新する。恒常アニメーション自体は端末設定に従う。3日・14日を新しい段階や演出の節目にはしない。これらの日数で初めて観測した未消化の1日・7日等は、通常の追いつき再生規則に従う。

| 根拠となる日数 | 表示段階 | 次に変わる節目 |
| --- | --- | --- |
| 0日 | 初期モノクロ | 1日 |
| 1〜6日 | 1日段階 | 7日 |
| 7〜29日 | 7日段階 | 30日 |
| 30〜59日 | 30日段階 | 60日 |
| 60〜99日 | 60日段階 | 100日 |
| 100日以上 | 100日段階・完成形 | なし |

- 初版の各段階は試作Bの対応する節目の姿を基準にする。表示段階の日数をsとし、x=s/100から、色はxの0.72乗、模様は1.15乗、発光は1.5乗、追加装飾は1.7乗、動きの強さは1.2乗を求める。生の日数をxへ使わず、節目間を補間しない。0日では装飾を出さず、1日で完成形にしない。100日以降はBの完成形を保持する。

## 見た目の適用範囲と描画

| 場所 | 適用する見た目 |
| --- | --- |
| ログイン後のホーム・友達・マイページ・ナビゲーション・外枠 | 本人の獲得済み見た目 |
| チャット内の背景・吹き出し | 共有成長と共有プリセットを優先 |
| 入力欄・エラー・重要な確認・送信状態の説明 | 読みやすさを守る標準の配色と表面 |
| ログイン・登録・認証コールバック | 成長による装飾なし |

- ルートのThemeProviderだけで全画面を装飾しない。認証済みの適用境界を設け、独立した会話ルートも含める。画面内にある再送・ログアウト等の重要な確認にも保護された表面を使う。
- 共通の見た目計算は確定日数、プリセット、明暗、派手さの設定を入力とする。同じ入力なら同じ結果とし、描画ごとの乱数や端末ごとの色抽選を使わない。
- ライト・ダーク別の配色を用意し、成長やプリセット変更で土台の明暗を逆転させない。基準Bの100日では、背景・外枠・会話内の面にライトの#ffe784・#fff4b6・#fff5db、ダークの#201627・#2b1b32・#211925を使う方向性を保持する。文字は各面に対して読みやすい色を選ぶ。
- 導入済みのreact-native-svgとreact-native-reanimatedで描画し、WebView、新しい描画エンジン、外部の演出サービスは追加しない。静的な模様・ステッカーと、少数の動く装飾レイヤーを分ける。
- 恒常的な動きはゆっくりした背景に限る。動かすのは装飾の位置・回転・不透明度等で、本文・入力欄・操作ボタンは揺らさない。本文のリストや入力を毎フレーム再描画せず、背景演出でレイアウトの再計算を繰り返さない。
- 画面外・バックグラウンドの恒常アニメーションを止める。テーマ・成長・共有設定だけで画面を再マウントせず、入力、選択相手、スクロール位置を維持する。既存の幅900以上・文字倍率1.3以下の2列条件は変更しない。
- 通常の文字は合成後の面に対して4.5:1以上、意味のある操作境界・アイコンは3:1以上を確保する。飾りだけを読み上げ対象にせず、日数・状態を色だけで伝えない。
- 小画面、横向き、文字200%、安全領域、キーボードを考慮する。新しい操作はiOSで44pt以上、Androidで48dp以上のタップ領域を持ち、装飾でフォーカスや既存操作を隠さない。

## 成長状況の表示と端末設定

- 会話ヘッダー付近に実際の成長日数と次の節目までの日数を表示する。当事者自身の一覧には小さな成長の印を出し、未読バッジの意味や並び順は変更しない。
- 本人については現在のストリーク、獲得済みの見た目段階、次の節目を区別する。現在0日・earned_days=29なら「獲得済み：7日段階」「次の30日段階まであと30日」と表示する。保持値29を「29日段階」と呼ばず、その差だけから「あと1日」としない。
- 次の節目は獲得済み段階より上の1・7・30・60・100日から選び、本人の残り日数はその値と現在のストリークから求める。チャットは累計との差を使う。100日段階獲得後は最大段階に到達と表示し、架空の次の節目を作らない。
- マイページに「派手／控えめ／オフ」を置く。初期値は派手。控えめは色を保ち、恒常的な動き・節目演出を止めて補助装飾を減らす。オフは装飾と色づきを止め、選択中のライト・ダークに対応するモノクロへ戻す。どちらも獲得や共有設定を削除しない。
- チャットとストリークの節目演出を種類別にオン・オフでき、初期値は両方オン。種類別停止は節目演出だけを止め、普段の色・模様・成長を変えない。
- 派手さと種類別停止は端末設定として保存する。ログアウト後も保持し、同じ端末の別アカウントにも適用する。他端末へ同期せず、マイページから再開できる。
- OSの動き軽減を起動時、設定変更時、アプリ復帰時に反映する。派手設定でも恒常的な動きを止め、節目は動かない達成表示に置き換える。控えめ・オフをOS設定で派手へ戻さない。
- 動き軽減の起動時値だけを返すフックに依存しない。OS変更の購読と復帰時の再確認を含める。端末設定の読み込みが終わるまで節目演出を開始しない。

## 節目演出の状態機械

| 状態 | 動作と遷移 |
| --- | --- |
| 待機 | 確定状態と可視性から候補を判定する |
| 保存中 | 今回の最大2件をまとめて消化済みにする。成功後だけ再生へ進む |
| 再生中 | チャット、ストリークの順で各約2秒。スキップで選択待ちへ進む |
| 選択待ち | 現在の演出を止め、非モーダルの2択を出す。次の再生だけを待たせる |
| 終了 | 残りがなければ待機へ戻る。画面離脱等なら残りも終了する |

- チャットは該当会話が実際に前景表示されているときだけ候補にする。activePeerIdだけで可視と判定せず、画面のフォーカス・前景・選択相手・認証寿命を合わせて確認する。別の会話の演出を現在の会話へ出さない。
- ストリークはログイン後の主要画面で候補にする。重要な確認表示中は開始しない。再生途中に重要な確認を開いた場合も、現在と残りの演出を終了する。
- 節目は1・7・30・60・100日。対象ごとに最高の未消化節目を1件だけ選び、途中の節目を連続再生しない。同じ判定で両方あればチャット、ストリークの順とし、1回のバッチは最大2件・通常約4秒となる。
- 2つの達成を1つにまとめない。それぞれの対象と達成日数を別々に派手に表示する。音、振動、強い点滅は使わない。操作領域は独立させ、装飾の面は入力・スクロールのタッチを奪わない。
- 再生開始前に、その回の対象・最高節目とそれ以下をまとめて消化済みとして端末内に保存する。保存失敗なら両方とも開始せず、成長した見た目だけ反映する。保存後の中断で見逃す可能性を許容し、必ず最後まで見せることより重複防止を優先する。
- スキップは現在の1個だけを対象とする。「今回だけスキップ」か「今後の同種類も停止」を選び、後者なら全チャットの節目演出またはストリークの節目演出を止める。相手側の設定は変えない。次が別種類で有効なら続けて再生する。
- 選択待ちに自動選択の締切を設けず、入力・送信・画面移動を維持する。選択で永続保存に失敗した停止設定はその起動中だけ適用し、保存できなかったことと再試行を示す。
- 画面移動、選択相手変更、バックグラウンド移行、ログアウトで現在・選択表示・残りを終了する。すでに消化済みにした残りを次回再表示しない。
- 再生中の更新で節目の無制限な待ち行列を作らない。終了後は最新の確定値から再判定し、未消化の最高節目だけを次の候補にする。取得・描画・プリセット変更そのものは達成イベントにしない。

## 初回基準と端末内の演出記録

- SQLiteに、アカウント・種類・対象をキーとする演出記録を保存する。チャットの対象はそのアカウントにとっての相手の内部IDとし、会話レコード作成前後や友達関係の世代でキーを変えない。本人の対象は本人として区別する。
- 保持するのは対象を区別する内部識別子、初回基準に達したこと、その時点以下を含む消化済み節目、種類別停止の再開世代だけ。名前・User ID・本文・画像・達成内訳を演出記録に複製しない。
- 本人・各会話の最初の正規同期を、その対象の基準として保存し、そこまでの節目は演出しない。新端末・再インストール・初めて取得する会話も同じ。古い項目欠落キャッシュや未確認の仮の0日で基準を作らない。
- 0日の会話を正規に取得した場合も相手単位で基準を保持する。最初の送信でconversation_idが作られても基準を作り直さず、その後の1日達成を新しい節目として扱えるようにする。
- 初回基準の後、対象画面を開いたときに進んでいれば、最高の未消化節目だけを再生する。会話を一覧で更新しただけでは、初回・停止中を除き新しい節目を消化しない。
- 控えめ・オフ・種類別停止中は候補を積まず、取得した節目を後で再生しない。再開時は種類ごとの再開世代を進め、未取得だった対象も再開後の最初の正規同期で基準化する。この基準化までに進んだ分も復帰時のまとめ再生には含めない。
- 通常の背景移行・再起動だけでは再開世代を進めない。初回・停止の基準化と、未消化節目の通常の追いつき再生を混同しない。
- 演出記録の保存は成功・失敗を呼出側へ返す。既存テーマ保存の、失敗を無視してメモリ内動作へ落とすアダプターを消化済み記録に流用しない。
- ログアウトでは既存のアカウントキャッシュ・下書き・画像等を従来どおり削除し、この最小限の演出記録だけを明示的な例外として保持する。別アカウントから参照せず、旧セッションのタイマー・保存完了通知・演出を復活させない。
- 同じ端末での再ログインでは消化済みの節目を再表示しない。端末データ消去・再インストールを越える一度限りの保証はせず、再導入時は初回基準で過去の演出を抑制する。

## 移行と障害対応

1. 追加マイグレーションと後方互換のサーバー・Edge更新を先に導入する。既存の送信入力・応答項目と読み取り項目は削除しない。既存アプリは新しい装飾項目を使わず動作できるようにする。
2. 既存のlifecycleと必要なロックの下で、保持済みメッセージを会話・04:00日付・送信者でまとめ、両者が存在する日だけを挿入する。withdrawnでも受付事実を含める。日別記録から累計を設定し、半分だけ初期化された状態を公開しない。
3. 同じ導入時点の現在のストリークを0〜100へ制限し、本人の初期earned_daysにする。既存行は再初期化せず、後の再実行で獲得済み値や選択プリセットをリセットしない。バックフィルの重複実行でも加算を重複させない。
4. 新アプリを導入し、SQLiteの追加マイグレーションと対象ごとの初回基準化を行う。過去分の復元から節目演出を生成しない。
5. 分離環境と両OSの確認後に、承認された環境へ適用する。本番デプロイ・外部ジョブ登録・通常DBのresetはこの設計作業では行わない。

| 障害 | 動作 |
| --- | --- |
| DB内の成長更新失敗 | メッセージ受付を含む同一トランザクションをロールバックする |
| 送信の通信切断・応答紛失 | 未受付と断定せず、既存の同じIDで結果を確認する |
| 成長状態の取得失敗・オフライン | 最後の確定表示を維持し、未取得ならモノクロの確認中にする |
| 共有設定の結果不明 | 元の操作を保って確認し、別IDで自動再送しない |
| 未対応の版・プリセット | 解釈を推測せず、安全な表示へフォールバックする |
| 演出記録の読込・保存失敗 | 演出を始めず、成長の確定・表示や会話を止めない |
| 停止設定の保存失敗 | 起動中の選択を維持し、保存失敗と再試行を示す |

## 数値と順序保証

| 項目 | 契約 |
| --- | --- |
| 成長日の境界 | 04:00 JST以上、翌04:00 JST未満。受付時刻だけで判定 |
| チャット加算 | 会話ごとに1日最大1回。実際の累計は100日以降も増加 |
| 見た目の段階と上限 | 0・1・7・30・60・100日段階。段階間は固定し、100日以降は完成形を保持 |
| 本人の保持値 | earned_daysは0〜100で単調非減少。段階間の数値も保持 |
| 見た目と演出の節目 | 1・7・30・60・100日 |
| 節目演出 | 1件約2秒、最大2件をチャット→ストリークの順。選択待ち時間は別 |
| 追いつき再生 | 対象ごとに最高の未消化節目だけ。初回・停止分は基準化 |
| 初期端末設定 | 派手、チャット・ストリークの節目演出ともオン |
| 共有設定の競合 | サーバーの後の受付を採用。成功済み操作は再適用しない |
| 保存と再生 | 初回基準・今回の消化済み記録を保存してから再生 |
| 表示の優先順位 | 保護された読みやすさ→会話内の共有表示→本人の外枠表示 |
| 文字と操作の視認性 | 通常文字4.5:1以上、意味のある境界・アイコン3:1以上 |
| 対応する表示検証 | 両明暗、0〜100の全日数と101日、各節目前後、文字200%、小画面・横向き |

## テストと完了条件

- DB単体では両者の同時送信、同時刻、同日多重送信、日付境界、自由な会話、画像のみ、抽選未確定・失敗、withdrawn、同日再成立、別日再成立、100日超過を確認する。日別記録と累計の一致、失敗時の全体ロールバックを検証する。
- 個人状態では現在値と保持値、29→0でearned_days=29・見た目7日段階を保持すること、再達成29日までは見た目不変で30日到達時だけ次段階になること、日付順の復旧途中の最大値、導入時の現在値だけの初期化、再実行の非減少を確認する。既存の抽選・達成・リセット規則の回帰も通す。
- 認証付き境界では第三者・匿名・別アカウント、関係終了・ブロック・古い関係世代、不正プリセット・未知キー、SQLへの直接呼出し、本人状態の漏洩を検証する。設定の競合・同じIDの再実行・結果不明と後の変更の順序を実HTTPで確認する。
- リポジトリでは更新通知からの再取得、複数端末、同じrevisionの本人・会話状態、古い応答、ログアウト後の応答、キャッシュ項目欠落、オフライン、未対応版を確認する。共有設定だけで空の会話を一覧に追加しないことも確認する。
- 演出の状態機械は注入した時計・可視性・設定・保存結果で検証する。達成点は1・7・30・60・100日だけとし、1日・7日を消化した後の3日・14日で新しい演出が増えないこと、最高節目だけの選択、最大2件の順序、保存前に再生しないこと、保存失敗、保存直後の終了、1個ずつのスキップ、選択待ち、種類別停止、別種類の継続、途中離脱、停止世代、初回基準を網羅する。
- 端末保存では同じアカウントの再ログインで重複せず、別アカウントへ記録を適用しないことを検証する。ログアウト後は最小限の演出記録と端末設定だけが例外として残り、本文・画像・下書き・通常キャッシュは削除されることを確認する。
- 見た目の純粋関数は全プリセット・両明暗・0〜100の全整数日と101日・全派手さ設定を確認する。0→1、6→7、29→30、59→60、99→100の段階切替と、1〜6・7〜29・30〜59・60〜99・100日以降の装飾不変を検証する。初日と100日の差、明暗の維持、合成後の文字コントラスト、最大段階、リセット後も保持した段階と現在値から求める残り日数の案内を確認する。
- iOS・Androidで実際の描画を確認する。100日状態と節目演出中の入力・送信・スクロール、キーボード、安全領域、文字200%、小画面・横向き・2列切替、VoiceOver・TalkBack、OS動き軽減の起動中変更を確認する。ビルド成功やHTML試作だけで合格にしない。
- DBテストは専用の分離環境で行い、通常の開発DBや他作業のデータを消さない。既存の型検査、アプリ単体・統合、SQL、Edge、backend・journeyの回帰を維持する。検証環境・実測・未確認範囲を記録し、設計時点の予定と実装後の証拠を区別する。
