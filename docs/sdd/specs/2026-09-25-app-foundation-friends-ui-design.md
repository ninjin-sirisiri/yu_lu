# アプリ基盤・登録・友達管理UI設計

分類: architectural。設計①〜④をユーザーが承認済み。Markdownを正本とする。

## 目的と範囲

- 新しいユーザーが登録し、相手を見つけ、申請・承認によって友達になるまでを実データで完結させる。
- 共通ナビゲーション、登録、プロフィール編集、友達検索、招待、申請管理、友達一覧、端末内保存、自動送信、競合解決、申請関連のプッシュ通知を一つの実装単位とする。
- ホームとチャットは画面の枠・準備中表示まで。ホームには友達追加の入口を用意する。
- 毎日の抽選・進捗・会話機能、友達削除・ブロック操作、追加OAuth連携、毎日の通知は後続の実装単位。既存ブロック関係による検索・申請制限は今回扱う。
- 日本語、iOS・Androidを対象とする。日次処理の日本時間基準を維持し、テーマの時間帯指定だけ端末の現地時刻を使う。

## 採用構成と責務

- Expo Routerを採用する。比較したReact Navigation直接利用より、画面とURLの対応、招待・通知の入口を管理しやすい構成を選ぶ。
- 端末内保存はSQLiteを採用する。簡易キー・値保存より、送信開始・取り消し・状態更新を整合させやすい構成を選ぶ。
- 既存Supabaseの認証・データベース・画像ストレージを使う。更新は専用サーバー処理に集約し、操作ID、実行者の権限、期限、重複、競合を確認する。サービス用秘密鍵をクライアントに置かない。
- 画面層は入力・状態表示・画面遷移、端末処理は下書き・キャッシュ・送信待ち・再試行、サーバーは友達成立と公開プロフィールの確定を担当する。
- SQLiteのデータはアカウント単位で分離する。画像本体は端末の永続ファイル領域に保存し、SQLiteには参照を保持する。端末設定はアカウントデータと分離する。
- 通知・招待の入口は認証と登録状態を確認し、対象の最新状態を取得してから画面へつなぐ。
- UI試作は使い捨ての見た目検証であり、本番コードではない。モノトーン案を視覚設計の土台とする。

## 画面と起動

- スマートフォンの下部タブはホーム、チャット、友達、マイページの4つ。
- 友達タブは友達一覧を中心とし、友達を追加、申請への入口を置く。申請画面で受信・送信を切り替える。
- 友達追加画面にUser ID入力、自分の招待QR、リンク共有、QR読み取りをまとめる。
- マイページはプロフィール表示・編集、テーマ設定、送信状況、ログアウトを提供する。送信状況は未完了件数を示す画面上部の入口からも開ける。
- 未ログインならログイン、ログイン済みで登録未完了なら下書きを復元した登録画面を表示する。通常の新規起動では、登録済みならホームを開く。
- 手動タスクキルとOS終了は区別しない。プロセスが残っている場合は前回のタブ・詳細画面まで保持し、復帰時に最新状態を確認する。
- 招待・通知による起動は通常起動と区別し、ログイン・登録を経て目的の画面へ進む。
- 別タブから戻ると詳細画面を保持する。選択中タブの再選択はその先頭へ戻り、すでに一覧なら先頭へスクロールする。
- 戻る、タブ切り替え、外部リンク・通知による移動ではプロフィールの下書きを保存する。下書き保存だけでは公開・送信予約しない。
- 横幅900以上の論理サイズでは左の縦ナビゲーションと一覧・詳細の2列表示を使う。狭い場合や文字拡大で収まらない場合は下部4タブと1列へ戻す。選択中の相手・入力を保持する。

## 登録と初回案内

- Apple・Googleのみでログインする。同じ検証済みメールによる既存の自動連携方針を維持し、異なるメールのアカウントを自動統合しない。
- User IDと表示名を入力し、User IDは変更不可であることを確認して登録する。画像と自己紹介は登録後に設定する。
- User IDは2〜20文字の半角英数字・アンダースコア。前後の空白を除去し、大文字・小文字を区別せず一意とするが表示の大文字・小文字は保持する。確定後は変更不可。
- 入力中のIDは予約しない。確定時の重複は拒否し、入力を保持して類似IDの候補を案内する。候補も確定時の一意性確認を必要とする。
- 登録途中の入力はアカウント別に端末保存し、再起動で復元する。ID確定前は通常画面に入れない。
- 通常登録後、友達0人なら友達追加案内を先に表示し、あとでを選べばホームへ進む。スキップ後は自動再表示せず、ホームの入口を残す。
- 案内済み状態はアカウント単位で保存する。招待先確認へ到達した場合も案内済みとし、一般案内を重ねない。
- 招待経由では登録後に招待先確認へ直接戻る。期限切れなら説明して友達追加へ進め、登録内容は保持する。

## 検索と友達一覧

- User IDの途中一致を検索し、表示名検索は行わない。2文字未満は必要な文字数を案内する。
- 2文字以上で入力停止から300ミリ秒後に検索する。入力変換中は検索せず、古い結果で最新の結果を上書きしない。
- 完全一致、前方一致、その他の部分一致の順とし、同分類ではUser ID順。20件ずつ表示し、もっと見るで追加する。
- 候補に画像・表示名・User IDを表示し、選択後のプロフィールで申請する。自己紹介はそこで確認でき、友達になる前のStreakは見せない。
- 友達・申請済み・受信申請中の相手も状態付きで表示し、操作を現在の関係に合わせる。自分自身と、どちらかがブロックしている相手は除外する。
- 検索はオンラインで行う。保存した友達一覧を全ユーザー検索の結果として扱わない。
- 友達一覧は日本語向け文字列照合による表示名順、同名ならUser ID順。ふりがなを追加せず、漢字の読み順は保証しない。表示は名前順とする。

## 申請と関係の確定

- サーバーが受け付けた申請の有効期間は7日間。送信者は取り消し、受信者は承認・拒否できる。受信一覧に承認・拒否を置き、プロフィールも開ける。
- 送信・承認は直接実行し、拒否・取り消しは確認を挟む。申請中の重複は作らず、既存申請へ案内する。
- 反対方向の申請意思が揃えば友達成立とし、関連する未処理申請を解消する。成立通知は重複させない。
- 承認がサーバーで確定するまでは友達として扱わない。オフライン承認は受信一覧に承認を送信待ちとして残す。
- 成立時は現在の画面に留まり、友達になったことと次回抽選から対象になることを説明して表示を更新する。
- 受信・送信は申請日時の新しい順。送信は申請中と終了した申請を分け、有効期限を表示する。送信待ちは受付済み申請と区別する。
- 拒否後は送信側へ今回は成立しませんでしたと即座に表示する。拒否の明示・理由を出さないが、終了タイミングが伝わることを許容する。
- 終了した申請は送信側で終了後7日間表示し、その後一覧から外す。表示期間は再申請の待機期間ではない。
- 拒否・取り消し・期限切れ後は即時再申請可能。ブロック中や別の申請処理中なら不可。初版で検索・申請に製品仕様上の回数制限を追加しない。
- 再接続時に取消済み・期限切れなら承認を不成立にする。同じ操作が成立済みなら完了として扱い、二重実行しない。他の相手への操作は続行する。

## 招待とインストール引き継ぎ

- 招待は友達申請そのものではない。リンク・QRを開いたら相手を確認し、本人が申請を押す。開くだけで友達にならない。
- 招待は7日間有効で複数人に共有可能。有効なリンク・QRを再表示し、期限切れ時に新規発行する。手動再発行は確認して実行し、以前の招待を無効化する。
- QR読み取りはカメラと保存画像に対応する。カメラ拒否時も画像選択・User ID検索を使える。
- オフラインでも取得済み招待を共有でき、取得時点の期限を表示する。別端末での再発行を把握できないため現在の有効性は保証せず、開いた際にサーバーで検証する。新規発行・再発行はオンラインで行う。
- 有料の専用リンクサービスは採用しない。AndroidはGoogle Play Install Referrerを利用して招待情報を取得する。
- iOSはWeb案内ページの明示的な操作で招待をコピーしてApp Storeへ進み、ログイン画面の招待を貼り付ける操作で取得する。通常インストールの人はそのままログインできる。
- iOSの1回の貼り付け操作は、追加操作なしの自動復元方針に対する承認済み例外。自動クリップボード読取りを前提にしない。
- 招待は登録中も保存し、別の招待を開いても最初の招待を維持する。OAuth復帰で招待情報を失わない。
- 復元不能・不正な貼り付け内容でも登録を止めない。元のリンクの開き直し・User ID検索へ案内する。招待有効期間とインストール情報の保持期間を混同しない。
- 専用サービスの照合やApp Clipsを使う案は採用しない。両OSのストア経由の引き継ぎは未実機検証であり、実装時の検証対象とする。

## プロフィール更新

- 表示名は1〜15文字。前後空白を除去し、空白だけ・改行は禁止。同名を許可し、登録後に変更できる。
- 自己紹介は任意、200文字まで、改行可能。空に戻して削除できる。文字数は見た目上の文字単位で数え、改行は1文字とする。
- 画像は撮影・保存画像の選択、正方形切り抜き、削除に対応する。未設定は共通人物アイコンを使う。
- 入力画像は10MBまでのJPEG・PNG・HEIC。最大1024×1024のJPEGへ変換し、透過部分は白背景、表示は円形とする。
- 保存操作で画像を含む更新を送信待ちにする。画像アップロード後、サーバーで競合を確認して公開プロフィールをまとめて更新する。
- 画像失敗時に文字だけ先に公開しない。本人には変更予定内容と送信状態、他人には以前の公開内容を表示する。
- 未送信の再保存は最後の内容へまとめ、期限を最後の保存から24時間に更新する。送信中なら先行更新の結果を確認して後続を処理する。
- 未送信更新の取り消しは下書きを残す。下書きの破棄とは別操作。24時間超過後も内容を確認して新しい操作として再送できる。
- 別端末の更新と競合したら自動上書きしない。最新内容と自分の変更を項目ごとに比較し、適用する変更を選んでまとめて保存する。

## オフライン・エラー・順序保証

- 取得済みデータは再起動後も閲覧可能。最終更新時刻と最新でない可能性を表示する。
- 状態は送信待ち、送信中、結果を確認中、完了、確認が必要、不成立・期限切れを区別する。各画面と共通の送信状況で確認・対処できる。
- 送信開始前だけ取り消し可能。未送信承認の取り消しは申請の拒否ではない。送信開始と取り消しを整合させる。
- 受付後に応答が失われても失敗と断定しない。同じ操作IDで結果を照会・再試行し、成立事実を一度だけ反映する。
- 接続復帰・アプリ復帰で再試行する。一時失敗は5秒から倍増、最大15分間隔で小さなばらつきを加える。自動再試行では期限を延長しない。
- 送信待ち期限は24時間。超過した未送信操作を自動実行せず、内容と最新状態を確認して新しい操作として再送する。実行不能なら理由を説明する。
- 送信済みで結果不明の操作は、24時間超過だけで未実行と断定しない。結果確認を区別する。
- バックグラウンド送信はOSが許す範囲で試行し、実行されなければ次の復帰で再開する。タスクキル後を含め固定時刻の実行・期限内の送信完了を保証しない。
- 権限不足、失効、プロフィール競合を一時通信失敗として繰り返さない。個別不成立は他の無関係な操作を止めない。
- ログアウト時は未送信件数を説明し、確認後に破棄する。送信中・結果確認中は成立済みの可能性を説明してログアウト可能とする。
- ログアウト後はそのアカウントの自動送信と通知配信を停止し、端末内アカウントデータを削除する。再ログインではサーバーの最新状態を取得する。

## 通知

- 申請到着、承認・相互申請による成立、申請の7日間の期限切れをプッシュ通知する。拒否と招待リンク自体の期限切れはプッシュしない。
- 通知には相手の表示名と出来事を含める。相手の私的な日次進捗は通知しない。
- 友達タブの案内で本人が通知を有効にする操作をしたときにOS許可を求める。拒否しても申請確認・承認は利用できる。
- 許可済みでログイン中の全端末に配信する。表示中の端末はOSバナー・音を出さず、短いアプリ内案内と件数更新を使う。
- 古い申請到着通知を開いたら受信一覧で最新状態を確認し、終了済みなら説明する。有効なら対象が分かる位置を表示する。
- サーバーで成立した出来事を基準に通知し、操作の再送による重複通知を防ぐ。通知配信の遅延・失敗で申請の成立や期限を変更しない。

## 視覚設計とテーマ

- 承認済みモノトーン試作を基準とし、余白・読みやすさ・控えめな装飾を優先する。未着・返信待ち・完了などの状態は中立的に伝える。
- ライト、ダーク、端末に合わせる、時間帯で切り替えるの4モード。初期値は端末に合わせる。設定は端末ごとに保存し、ログアウトで消さない。
- 時間帯指定の初期値はライト07:00、ダーク19:00。両方を変更可能で、同じ時刻は保存不可。端末の現地時刻を使い、閉じている間に時刻を過ぎたら復帰時に反映する。
- 選択中の画面・入力をテーマ変更で失わない。文字拡大、読み上げでの操作、色以外の状態表示、ライト・ダークそれぞれの可読性を検証する。

## 既存仕様との関係

- CONTEXT.mdのFriend、Chat、Streak、Send Target、Reply Target、User ID、Friend Request、Invitationの意味は変更しない。画面名や保存方式は実装上の事項であり、用語集へ追加しない。
- 2026-09-11の友達登録仕様に対し、User ID検索を部分一致候補一覧へ拡張する。候補選択後に1人のプロフィールを確認する。
- 同仕様の拒否タイミング非公開要件を変更する。拒否の明示・理由は非公開だが、即時終了表示でタイミングが伝わることを許容する。
- 招待期限切れの案内は画面内だけとし、申請期限切れのプッシュ通知とは区別する。
- この3点の相違は本仕様を優先する。他の確定済み業務ルールは既存仕様を継承する。日次チャット仕様を今回のUI実装済み機能と誤認しない。
- ADRは作成しない。今回の技術選択について、取り消し困難・文脈なしでは意外・実際のトレードオフの3条件がすべて成立する判断は採用していない。

## テストと完了条件

- 登録の重複ID、登録途中の復元、アカウントをまたぐデータ分離、変更不可IDを検証する。
- 部分一致、完全一致優先、追加取得、古い結果の抑止、ブロック相手除外、友達になる前のStreak非表示を検証する。
- 相互申請、重複送信、承認と取消・期限切れの競合、終了表示、再申請、拒否通知なしを検証する。
- オフライン操作の再起動復元、送信開始と取消の競合、応答喪失、24時間期限、ログアウト中の停止を検証する。
- 画像失敗時の非公開、再編集統合、下書き保持、項目別競合解決、文字数境界を検証する。
- 招待再発行による失効、登録中の失効、最初の招待の保持、復元不能・不正リンク時の案内を検証する。
- 複数端末通知、ログアウト後の停止、表示中の案内、古い通知からの移動、重複配信抑止を検証する。
- ライト・ダーク・時間帯変更、同時刻拒否、文字拡大、1列・2列切替時の入力保持、タブ再選択を検証する。
- 自動テストは境界値・状態遷移・サーバー権限・再送の整合性を対象とし、画面から登録・申請・承認・プロフィール更新が完結する結合経路を確認する。
- 実機でカメラ・画像・QR、プッシュ、バックグラウンド処理を確認する。AndroidはGoogle Play経由のインストール、iOSはインストールを挟む明示的貼り付けと拒否・消失時の復帰を検証する。
- 調査資料は動作証明ではない。Expo 57とReact Native 0.86.3の実プロジェクトでビルド・型検査・関連テストを実行し、ストア経由の検証結果を記録して初めて対応する完成条件を満たす。
