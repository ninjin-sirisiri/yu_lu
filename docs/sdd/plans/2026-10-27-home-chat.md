# Home and Chat Implementation Plan

**Goal:** 承認済み仕様に従い、ホームの今日の行動・達成表示と、友達とのテキスト・画像送受信を実データで完結させる。

**Architecture:** 既存のapp-query／app-command、アカウント別SQLite、共通送信キューを拡張する。会話を友達関係から分離し、日次台帳、受付の重複防止、会話別FIFO、本人専用の閲覧状態で整合性を守る。リアルタイムは本人向けの更新通知に限定し、再取得で回復する。

**Tech Stack:** Expo SDK 57、React Native 0.86.3、React 19.2.3、TypeScript、Expo Router、expo-sqlite、expo-file-system、expo-image-picker、expo-image-manipulator、Supabase Auth/Postgres 17/Storage/Edge Functions/Realtime、Jest、React Native Testing Library、pgTAP、Deno tests。

**Spec:** docs/sdd/specs/2026-10-27-home-chat-design.md

## Global Constraints

- 全ての現在の友達と自由に会話できる。今日の割り当ては達成条件であり、会話できる相手を限定するものではない。友達成立後、次回抽選を待つ間も会話できる。
- メッセージの編集・編集履歴操作・送信済みメッセージの取消、音声・動画・通話、ランキング、会話内容の採点、自動画像審査、会話検索は対象外。
- 友達解除、ブロック・予約、ミュート、非表示、通報の操作画面は別の設計単位。今回も既存の関係保護を維持し、関係変更後の履歴アクセス・送信停止を扱う。
- プッシュ配信・OS通知許可要求・日次通知・メッセージ通知からの起動は対象外。Apple Developer Program加入後に別途実装する。アプリ表示中の新着反映とバナーは今回扱う。
- 日次境界: 04:00 JST。抽選確定期限: 04:05 JST到達前。達成対象は当日04:00以上、翌日04:00未満のサーバー受付分。
- 本文: 10,000拡張書記素クラスタ。判定版: Unicode 17.0.0、UAX #29 Revision 47。改行はLFで1文字。
- 添付: 最大4枚、元画像と変換後の各画像は10MiB以下、元形式はJPEG・PNG・HEIC、送信形式はJPEG・PNG。縮小後の長辺は最大2048px、JPEG品質80%。
- 追加取得: その他の会話20件、メッセージ50件。今日の対象者はこの会話件数制限とは別に全員表示する。
- 閲覧画像キャッシュ: 100MiB。自動送信期限: 予約から24時間。再試行: 5秒から倍増、最大15分間隔、既存のばらつき付き方式。
- 適応表示: 論理幅900以上かつ文字倍率1.3以下で2列、それ以外は1列。画面内の選択・下書きを維持する。
- 日次処理は締め、関係変更、抽選の順。送信は端末・アカウント・相手ごとにFIFO。表示する確定履歴は会話内のサーバー受付順。返信は受信より厳密に後、受付時刻同値は不成立。
- 通常の閲覧は表示した受信メッセージだけ未読を解消する。最新へを明示的に押した場合に限り、移動先として取得した最新位置まで途中も含めて解消する。その取得後に届いたメッセージまで巻き込まない。
- 関係終了を確認した端末は送信待ちを停止する。再び友達になった場合は同じ履歴を引き継ぎ、本人が確認した新しい送信だけを受け付ける。停止中のものを自動復活させない。
- 本文と受付済み画像は会話の当事者だけが取得できる。友達解除・ブロックの適用後も過去分の閲覧を許可するが、新規送受信は許可しない。ブロックされた事実は明示せず、現在この相手には送信できませんと表示する。既存の取消済み行は本文・画像を隠し、受付事実だけ維持する。
- ログアウト時は未送信件数と結果不明の可能性を説明し、確認後にそのアカウントの自動処理を停止してSQLite・永続ファイル・画像キャッシュを削除する。別アカウントの資格で送信・画像取得・イベント購読を再開しない。

## Execution and verification contract

- Taskは番号順に実行し、一つずつ完了判定する。各Taskのテストを実装前に失敗させ、同じコマンドを実装後に再実行する。記載のファイル・関数名は作成する実体であり、雛形や成功を返す仮実装で完了にしない。
- コマンドはリポジトリルートで実行する。DBの前提確認は`npx supabase start`、追加変更の適用は`npx supabase migration up --local`。既存データを消すreset、remote／linkedへの変更は実行しない。DBテストはトランザクションで巻き戻す。
- アプリコードを書く前に`app/AGENTS.md`とExpo SDK 57の該当APIを読む。依存は既存package.jsonを優先し、SDK整合性は作業ディレクトリapp/で`npx expo install --check`を実行して確認する。Context7はlibraryで解決してからdocsを取得する。
- SQLの時刻注入は非公開ヘルパーとDB所有者のテストだけで使う。公開RPC・HTTPは必ずサーバー時刻を採用し、テスト用の日付指定・認証迂回エンドポイントを出荷しない。新しいSECURITY DEFINER関数は空のsearch_pathと明示的なEXECUTE権限を持つ。
- Task 10以降の新しいHTTP／画面通しテストは専用スタックを使う。通常の`daily-chat`プロジェクト、54321系ポート、`app/.env`を変更しない。既存の基盤テストは元の環境で別に回帰確認する。
- 各Taskの完了前に`npm --prefix app run typecheck`と`git diff --check`を実行する。DB変更Taskは追加適用後に全pgTAPも実行し、既存の登録・申請・プロフィール権限を壊していないことを確認する。
- コミットはそのTaskのファイルだけを明示的にstageし、無関係なユーザー変更を含めない。実装時のコミット・PR単位はTask Nであり、Task内の手順を独立PRにしない。未実行・機材不足は成功やskip済み完了に置き換えない。
