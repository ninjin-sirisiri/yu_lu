# Yu_Lu 紹介動画

MBC U-20 NEXT PROGRAMMING CONTEST向けの、音声だけで説明が完結するRemotion動画です。
1920 × 1080、30 fps、尺は242.83秒（約4分3秒）です。全編MP4は `out/Yu_Lu.mp4` に書き出し済みです（H.264 / AAC、14.4 MB、SHA-256 `852d114c5af29751dc3e7574d4812f431af7a697a40e3c36d0315ada431a5e70`）。

## プレビュー

このディレクトリで実行します。生成済みの音声と素材を含むため、見るだけならVOICEVOXは不要です。

```sh
npm ci
npm run dev
```

Studioの `YuLu` を開きます。現在のセッションでは <http://localhost:3000/YuLu> で起動しています。
ソースをまとめて更新した直後に表示が不自然になった場合は、Studioのページを再読み込みしてください。

## 台本と音声の変更

- `content/script.json`：台本、画面上の見出し、声の設定。編集元はこのファイルです。
- `text` は字幕、`speech` は読み上げ専用です。アプリ名は字幕を `Yu_Lu`、読み上げを `ユール` にしています。その他の英語の固有名詞も、字幕を英字にし、`speech` にカタカナの読みを残しています。
- 発話内の `cues` はVOICEVOXが解析したカタカナの音素列に対応します。`phrase` が一意に見つからない場合は生成を止めます。
- `content/narration.md`：読み合わせ用に生成する台本。直接編集せず、JSONを変更します。
- `public/audio/`：VOICEVOXで生成したWAVと、生成条件・チェックサム。
- `src/generated/`：実測尺のタイムライン、字幕、実演映像の情報。

VOICEVOXエンジンをローカルの50021番ポートで起動してから実行します。

```sh
npm run voice
```

エンジンがなければ、Docker起動後に別のターミナルで公式のCPUイメージを使えます。初回は大きなダウンロードが発生します。

```sh
npm run voice:engine
```

接続先を変える場合は `VOICEVOX_URL` を設定します。現セッションでは、公式Mac版エンジン0.26.0を一時ディレクトリに展開して起動しました。常設インストールは行っていません。

初期設定は四国めたん・ノーマル、話速1.0です。`voice.speaker` と `voiceCredit` は対応する値へ一緒に変更します。
使用できる話者とスタイルIDは、エンジンの `/speakers` で確認できます。

音声は、本文・声・設定・エンジンバージョンをキーにキャッシュします。WAVの実サンプル数から各発話の尺を求め、前後の短い間を加えて映像と字幕を配置します。
発話の終わりから次の発話までの間は約0.25秒です。発話音声そのものは削らず、旧構成の約0.75秒から切り替えを0.5秒短縮しています。
再生速度を自動変更して5分へ収める処理はありません。5分を超えた場合はエラーになるため、台本を短くしてください。
字幕は発話単位で同期しています。タイトルは `scenes[].title` を章の間固定し、字幕ごとには切り替えません。`lines[].headline` は台本の編集メモとして残していますが、スライドのタイトルには使いません。
中央の図は `src/visuals/` に分け、友達の選択・メッセージの移動・日数の記録・送信待ちの列などを、話の進行に合わせて動かします。音声と字幕は独立した区間に配置しています。
3章の図は「自分・友達A・友達B」を維持し、`自分→A` と `B→自分` を別の色と経路で描きます。同じ2人の往復にはしません。相手が異なる場合の例であることも図中に表示しています。
矢印や日数の強調には、合成時の `audio_query` の音素長・間・前置無音・話速から算出した発音開始時刻を使います。文字数による推定ではありません。実際の音声との丸め誤差はあり得るため、変更した発話は試聴してください。

## Simulator素材の撮影

実際に表示している画面を撮影します。撮影後に画像を開き、読み込み中や個人情報が写っていないか確認してください。

```sh
npm run capture -- --device <SimulatorのUDID> snapshot chat --note '実際に表示したチャット一覧'
```

画面遷移の実行映像は、生成済み音声の尺を使って等速で撮影できます。

```sh
npm run capture -- --device <SimulatorのUDID> record-navigation --peer <検証用の友達のUUID>
```

この操作はアプリのディープリンクでチャット一覧・友達一覧・既存の会話を開きます。メッセージ送信、友達申請、認証の変更、DBへの直接書き込みは行いません。
録画時間は音声のタイムラインに合わせます。ナレーションの尺を変えると古い録画は無効になり、撮り直すまで静止画へ戻ります。

`public/demo/navigation.mp4` は素材用の実行映像であり、提出用の完成動画ではありません。
`public/screens/*.json` と録画のJSONには、撮影方法とチェックサムを残しています。

### 成長・ストリークの表示プレビュー

5章は `growth-1/7/30/60/100.png` の実画面を、日数の読み上げに合わせて切り替えます。バッジの点灯も同じ時刻を使い、最後の100日段階を章末まで保ちます。
6章には `streak-1.png`、`streak-100.png`、`streak-reset.png` を使い、現在0日になっても獲得済み100日段階が残る表示を紹介しています。
いずれも開発用の表示プレビューで、達成の実績やDBは変更していません。

撮り直す場合は開発ビルドで、既存の画面のクエリを使います。各URLを開き、表示を目視確認してから `capture snapshot` で撮影してください。

- 会話画面：`app://conversations/<peer UUID>?origin=chat&capturePreview=growth&captureDays=30`
- ホーム：`app://home?capturePreview=streak&captureDays=100`
- 連続日数リセット後の表示：`app://home?capturePreview=streak&captureDays=100&captureReset=1`
- **撮影後は必ず復元**：`app://home?capturePreview=restore`

受け付ける日数は0・1・7・30・60・100だけです。`DevCaptureObserver` は開発ビルドだけに配置し、既存のプレビューストア以外へは書き込みません。成長と個人の表示を独立して変更し、一連の撮影開始前のプレビューを復元します。

## 提出前に補いたい実演

現在の動画には、次の制約があります。

- 実行映像は約40秒の画面遷移です。新規メッセージの送信・相手側での受信は収録していません。
- 撮影時のホームは「今日の相手を確認中」でした。割り当てが確定したホームから送信する実演は未収録です。
- 成長段階と個人のストリークは、各段階の表示プレビューを撮影済みです。日数が実際に経過した記録や、実績を獲得する瞬間の映像ではありません。
- `home.png` は撮影時に有効だった個人の100日段階の表示用プレビューです。実際に100日継続した証拠ではありません。
- Simulatorのスクリーンショットとディープリンクでの画面遷移は使えましたが、Orcaのタップ操作はXcodeの `SimulatorKit.framework` が見つからず失敗しました。XcodeやOrca自体の修正はしていません。
- 台本の今後の検証方針は提案段階の文章です。実際の開発者の意図と一致するか、提出前に読み合わせてください。
- 全編の人手による試聴、発音と字幕の読みやすさ、最終提出ファイルの確認は残っています。

次に、同意した検証用アカウントで送信・受信・返信まで撮影し、画面遷移の素材と差し替えると、主要機能の実演を補えます。
実データの送信や日次抽選の状態変更は、撮影のために勝手に実行していません。

## 検査と書き出し

```sh
npm run check
npm run build
```

検査では、実測尺、5分上限、音声の切れ、素材のチェックサム、古い台本・録画の混在を確認します。
音声の再生成は `npm ci` のライフサイクルには組み込んでいません。

3章の動きは `out/concept-motion-preview.mp4`、5章の動きは `out/growth-preview.mp4` で確認できます。全編の書き出しは `out/Yu_Lu.mp4` です。代表フレームは `out/final-check/` にあります。

再出力するときは、内容を確認したあとで明示的に実行します。

```sh
npm run preflight
npx remotion render src/index.ts YuLu out/Yu_Lu.mp4
```

Remotion 4.0.539が指定するZod 4.5.4には脆弱性の警告があったため、同じ4系の修正版4.6.6へ統一しています。
このためRemotionのバンドル時にバージョン不一致の警告が出ます。型検査・バンドル・フレーム出力で動作を確認し、今後Remotion側の対応版が出たら指定を見直してください。
実装時の `npm audit --omit=dev` は0件でした。開発用依存にはmoderateの警告が残っており、Studioを公開サーバーとして運用する想定ではありません。
